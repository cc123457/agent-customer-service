# 记忆修复与费用计量：原来、改后和原因

本轮保留原来的SQLite默认配置，没有迁移到MySQL。修复源文件已写回原项目；评测只使用独立临时数据库和测试Redis命名空间。旧评测、原始回答及人工评分均保留。

## 1. 预算更正：同一属性不再按整句话生成不同键

位置：memory/fact_rules.py的note_key、normalize_candidate、current_rows；memory/long_term.py；db/memory_repository.py的_apply_memory、search_memories、active_memories。

原来“配件预算上限是2504元”和“配件预算上限改为2604元”分别对完整文本做哈希，生成两条note键。两条均被标为有效，模型需要自行判断哪个更新。

现在对有限预算类型使用稳定键：配件note:budget:accessories、设备note:budget:device、一般采购note:budget:purchase；房间对象仍按现有entity隔离。其他自由笔记继续按内容哈希，不擅自把任意同义表达合并。原文值保持不变，SQL同一事务内更新当前值、保留事件并推进Redis版本。

旧库的哈希预算笔记由读取层按对象/预算类型选择最新来源，避免未经写入迁移时还同时召回旧值；新预算写入会将匹配的旧哈希行标为superseded。向量候选最终按完整SQL当前集合复核，不能只因旧ID仍存在于向量库就恢复旧预算。原始消息不删除。

## 2. 明确生效日期：先存计划，到期再换当前事实

位置：memory/fact_rules.py的explicit_effective_date、effective_timestamp；memory/fact_extractor.py；db/memory_extensions.py的memory_scheduled_facts；db/memory_schedule.py；db/memory_repository.py的memory_version。

原来MemoryCandidate虽然有valid_at字段，规则常漏填；即使模型填了，SQL仍立即覆盖当前事实，没有实际时间激活机制。

现在规则和模型候选使用同一规范化，支持明确ISO日期及带时区时间；“从2026-12-10起”按UTC+8的12月10日零点生效。非法日历值或同句多个作用域不明日期不会写成即时事实。没有明确时间时仍按即时事实处理，不猜相对日期。

例如当前是瓷砖，用户在11月24日说12月10日起改木地板：当日只新增未来计划，当前仍为瓷砖；12月10日后的首次读取在用户写锁短事务里激活计划、保存事件并推进缓存版本，之后才返回木地板。无需依赖后台定时任务。

版本SELECT附带最近计划时间的标量子查询，普通缓存命中仍只需要一条SQL往返。跨生效点才进入写事务。MySQL锁用户行；SQLite先执行等值UPDATE获取写锁，避免仅依赖SQLite不实现的FOR UPDATE。Redis TTL未到也会因新版本而失效。向量索引仍需SQL复核。

自然语言遗忘和管理删除会取消对应未生效计划；若有比计划更新的明确陈述，旧计划不会覆盖更晚的来源。未来计划数量受现有记忆条数配额约束。表通过create_all增建，不ALTER原档案。

边界：这是按真实时钟激活的有限生效计划，不是任意时间点的完整双时态数据库；未增加专门的“查询未来计划”管理接口，任意相对时间、复杂多日期语义及计划记录长期物理清理仍需后续设计。软删除也不等于抹除原始档案。

## 3. 摘要：保留关键编号、日期及时间原文

位置：memory/batch_summary.py的_prompt、preserve_identifiers、summarize。

原来摘要只要求保留约束、型号和已尝试操作，模型曾在型号更正后漏掉维修登记号，也可能让重复日常观察挤掉重要信息。

现在提示词优先省略重复观察，明确保留维修/授权/批次编号、日期和时刻，并区分问题发生时段与最终安排。每批模型输出后检查原输入关键标识；遗漏时补充包含该标识的原文短句，并标为历史参考，不能自动当成当前事实。比较编号使用边界匹配，X100不能代替X10。

补原文仍受summary_budget约束。必要短句本身放不下时明确失败，原来的摘要水位和原文保留，不提交遗漏关键编号的结果。不把所有事实都塞入摘要，也不声称这种有限标识检查可以检测全部语义错误。

## 4. 回答与拒答：共用证据使用策略

位置：memory/answer_policy.py；agent/react_agent.py初始化系统提示；scripts/evaluate_history.py的answer_one。

原来模型曾把凌晨噪音发生时间答成调整后的运行时间；遗忘题文字正确拒答却输出abstain=false；偏好题误把JSON接口格式当成用户偏好。

现在生产Agent和离线回答共享策略：区分当前事实和历史原话、未来计划和已生效事实、原问题时段和最终安排；证据不足说明具体缺口；只有真实遗忘要求才提遗忘；若调用方要求answer/abstain结构，文字拒答与布尔值必须一致。所有对照方案使用相同回答策略，避免只给当前方案额外提示。

补测还发现：SQL返回“瓷砖”，但历史里有“明天起改木地板”时，模型仍可能选后者。memory/context_builder.py现在说明当前事实已核对生效时间；共用策略明确查询当前值时优先使用该事实，消息说出时间不等于生效时间。问过去时点仍按对应原文判断，历史计划原文继续保留，不为了提高分数删掉它。首次失败记录与后续修正复测分别保存。

跨月题继续暴露仅靠提示词不够，因此context_builder.py增加pending_plan_label：复用fact_rules里的明确日期解析，比较生效时刻和本轮as_of，对未到期计划添加“尚未生效”元信息。ChatService.open_turn传入repository.clock()，和SQL激活使用相同时钟；历史片段与近期旧轮次使用相同规则，本轮用户原话不改写。原文、来源及未来日期继续保留，完整包装也计入原上下文预算，近期/历史去重仍生效。到期或模糊/非法/多日期作用域不明时不伪造该标记。这是日期计算后提供证据元数据，不是用金标准替模型填答案。

日常聊天仍输出自然语言，没有强迫每轮都返回JSON。abstain是本轮结构化评测约定，并非已有生产聊天接口的通用字段。本轮没有用关键词正则偷偷翻转模型的abstain或把标准答案写进输出。策略会影响模型行为，但不保证每次都正确，失败仍保留在分母。

新运行将完整回答系统提示保存到manifest，便于复核原模型实际输入；旧运行仍按旧基线重建，避免后来修改提示词影响历史评审。

## 5. Embedding及模型费用：先读取真实usage，再计算参考原价

位置：model/usage.py；model/factory.py；scripts/evaluate_history.py的CountedModel/CountedEmbeddings和案例账本；scripts/report_memory_cost.py；config/model_prices.yml。

原来LangChain的embed_documents只返回向量，丢弃响应usage，因此只能记录SDK操作数与字节量，无法计算精确Embedding Token。本轮在SDK末端create返回时、LangChain丢弃usage前采集用量；向量、批量上限和重试策略不变，同步/异步路径都覆盖。

账本用ContextVar绑定案例和阶段，线程安全记录，并行案例不会混账。索引文档与查询、摘要与各方案回答分别记录。诊断用的三路检索和实际聊天各有索引，不能让当前方案借用诊断预热，也不把诊断建设量算成当前方案费用。

当前方案单次冷启动参考费用＝其实际建索引Embedding＋查询Embedding＋摘要输入/输出＋回答输入/输出。本次历史评测的事实提取使用规则，没有模型抽取费用；若以后启用模型抽取，也应单列并计入。不能把其他对照方案的模型调用混进去，也不能把一次性准备费用省略后称总成本下降。

参考价采用2026-11-24查阅的百炼北京地域同步纯文本原价：qwen3.5-omni-flash输入2.2元/百万Token、输出13.3元/百万Token；补测qwen3-omni-flash输入1.8元/百万Token、输出6.9元/百万Token；text-embedding-v4输入0.5元/百万Token。来源：[原聊天模型价格](https://help.aliyun.cn/zh/model-studio/qwen3-5-omni-flash)、[补测模型价格](https://help.aliyun.com/zh/model-studio/qwen3-omni-flash)、[Embedding价格与usage示例](https://help.aliyun.com/zh/model-studio/embedding-interfaces-compatible-with-openai)。不同地域、兼容服务折扣、优惠和免费额度可能影响实际账单，本配置只作参考。

用户说明使用百炼免费额度。因此报告同时保留free_quota_reported_by_user=true、actual_bill_paid=null；不读取余量/账单时不伪填实际支付为0。usage缺失或请求失败时保留缺失项，只给已知小计，不用字节数推算Token。SDK内部重试没有单独暴露时，也不把操作数称作全部HTTP尝试次数。

## 6. 配额耗尽后的补测与JSON格式兼容

位置：scripts/evaluate_history.py的RequestGate、answer_one及--chat-model参数；scripts/evaluate_memory_quality.py；services/json_payload.py；services/structured_output.py；memory/fact_extractor.py。

原qwen3.5-omni-flash先完成48题回归，随后在新增题上返回403。用户确认额度耗尽并授权使用其他有免费额度的模型，因此仅对评测进程传入--chat-model qwen3-omni-flash，重新执行原48题、新增24题及抽取/摘要固定集。config/rag.yml默认模型没有改变；不同模型分开汇总，不把跨模型差异说成代码优化效果。Realtime候选没有用于这次Chat Completions补测。

以前403可能在多个案例继续重复请求；现在同一运行首次遇到401/403后停止后续模型调用，将未执行项明确记为not_run_model，并保留在计划案例记录里。不会伪装成功或将失败Token当成0费用。SDK内置的一次重试设置仍按原配置执行；429等暂时错误没有被当成永久鉴权阻断。

新模型校准还发现：字段内容正确的JSON有时末尾多一个Markdown代码围栏。原来直接model_validate_json会拒绝它；现在json_payload只去掉外层开头/结尾围栏，之后仍进行同样的Pydantic字段、类型、额外字段及业务原文依据校验。不会从任意解释段落里挖JSON、补写字段或修补语义。评测保留raw原文和format_normalized标记。这仍是JSON模式与本地校验，不声称服务支持原生严格Structured Outputs。

## 验证与结果文件

旧48例用于修复回归，不称新的独立验收；evals/refinement_cases.json另编24例，覆盖不同预算、真实已入库未来计划、不同调整时刻和遗忘。新题的计划在提问前已说出，不能靠删除提问后的消息假装验证生效机制。另重新运行原抽取/摘要固定质量集，查看改动是否破坏原行为。

测试覆盖预算更正与旧哈希兼容、向量旧ID复核、UTC+8生效边界、取消计划、更新来源优先、真实Redis跨日期版本失效、摘要编号保留、SDK分批用量、并行费用隔离及成本归属。可运行命令：

```powershell
python -m pytest tests/test_memory_refinement.py -q
python scripts/evaluate_history.py --live --chat-model qwen3-omni-flash --split test --env-file .env --min-call-interval 1.5 --output evals/runs/NEW-refinement-regression
python scripts/evaluate_history.py --live --chat-model qwen3-omni-flash --dataset evals/refinement_cases.json --split test --env-file .env --min-call-interval 1.5 --output evals/runs/NEW-refinement-acceptance
python scripts/evaluate_memory_quality.py --live --chat-model qwen3-omni-flash --suite all --split test --env-file .env --min-call-interval 1.5 --output evals/runs/NEW-refinement-quality
python scripts/report_memory_cost.py --source evals/runs/NEW-refinement-acceptance --free-quota-reported --output evals/runs/NEW-refinement-cost.json
```

最终日期标记修正后的全量回归183 passed、94 skipped、1个既有依赖警告，25.96秒。真实SQLite及本机Redis 6379/15启用，REQUIRE_REDIS=1；94个跳过项均未配置测试MySQL，不表示项目已迁移数据库。新增用例还验证了401/403阻断、围栏清理后严格校验、Embedding usage及费用归属，以及跨年计划标签、原文保留、上下文预算和近期/历史去重。没有进行线上容量压测。

最终实测指标、费用及简历建议见[记忆优化实测报告](记忆优化实测报告.md)；指标应明确内部离线范围、回答阶段Token和冷启动总参考费用，不能将三者混成一个“成本降低比例”。
