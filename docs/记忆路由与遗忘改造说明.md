# 记忆路由与遗忘升级：代码改动说明

本次改动位于 `D:\RAG\agent`。SQLite继续保存原文、摘要和长期事实；Redis缓存结构化事实。新增的是“什么时候读、允许读什么”的统一策略。旧版80题首测和原始回答保留，新版另外冻结40题进行同模型对照。

## 1. 按一次用户请求阅读代码

```text
api/deps.py：创建共享服务和统一分析器
    ↓
services/chat_service.py：open_turn()
    获得会话处理权，读安全的小段近期上下文
    ↓
memory/request_analyzer.py：analyze()
    读取计划 + 明确写操作 + 澄清状态
    ↓
db/memory_repository.py：start_request()
    一个事务归档原文、提交记忆操作、更新缓存版本和请求遗忘版本
    ↓
memory/access_policy.py + memory/history_retrieval.py
    过滤本人可用来源，按计划检索事实、笔记或历史
    ↓
memory/context_builder.py：compose_context()
    在既有预算内组合安全输入
    ↓
services/chat_service.py：reply_turn()
    需要澄清则直接询问；否则执行Agent，发送每个事件前复核遗忘版本
    ↓
db/memory_repository.py：finish_request()
    再次核验后保存成功回答
```

## 2. 统一分析：替换两套判断

入口：`memory/request_analyzer.py` 的 `MemoryRequestAnalyzer.analyze()`；装配：`api/deps.py`。

**改前：** `memory/fact_extractor.py` 只负责写事实；服务另外用 `history_query()` 判断是否查历史。明确字段和问候仍可能触发不需要的个人语义索引同步。没有问号的“请同时列出保修凭证和服务编号”容易漏检。模型提取在结构错误后最多再调用一次。

**改后：** 只保留一个分析器，返回 `MemoryPlan`。`read.fact_keys` 决定查哪些结构化字段，`search_notes` 决定是否启用笔记/语义召回，`search_history` 决定是否查历史；`operations` 独立保存明确陈述或遗忘。一次输入可以同时读、写。明确规则直接返回，不确定情况最多一次JSON Mode模型分析，Pydantic验证结构，然后校验证据、对象、日期和字段含义。格式或接口失败不再修复重试，保留确定规则和原文，退到有界保守检索。读计划子字段有误时，独立通过结构和原文校验的事实可以保留；未知顶层字段或事实本身无效仍拒绝。

例如“我用的是X10，怎么充电？”仍能写型号并回答问题；“我要求的回答详细程度是什么？”不会把问题中的“详细”写成新偏好。本人陈述识别不再枚举“我目前/我购买”等有限前缀，防止已知读取路由提前吞掉新的明确陈述。即使模型把问句片段作为候选，第二层原文语义检查也拒绝它。

分析器只带最近4条消息的有限片段及有限摘要；完整提示超过4096估算单位时，不截断后猜事实，直接降级。默认模型等待上限3秒、输出上限1000 Token。4096是本项目的输入估算单位，不是提供方精确Token。

原 `memory/fact_extractor.py` 已移除，当前服务、抽取评测和常规测试均改用新入口；对照评测的旧版本分支有意载入快照中的旧类。`extract()`只供抽取质量评测取统一分析结果里的写操作，不是另一条推理链。

**为什么在这些文件：** 分析器负责解释需求；服务负责调用顺序；数据库负责可信提交。分析器不接收认证用户ID作为模型输出字段，也不持有数据库写权限。

## 3. 遗忘：从一个状态改为持久读取约束

表结构：`db/memory_extensions.py`；事务逻辑：`db/memory_privacy.py`。

**改前：** 主要把某条事实标为deleted，再遮蔽已知旧值。某些自然语言删除表达识别不到，近期原文没有统一过滤，带过去日期的回查还可能保留被撤回的旧信息。

**改后：** 新增独立表，不手工ALTER旧档案表：

| 表 | 保存什么 |
|---|---|
| `memory_forget_rules` | 本人属性/对象、来源截止消息ID、已知旧值及创建时间 |
| `memory_forget_epochs` | 本人的遗忘版本 |
| `memory_request_epochs` | 本次执行使用的遗忘版本 |

`start_request()`在一个事务里保存用户原文和规则，停用匹配事实，取消尚未生效计划，解决相关旧冲突，作废本人旧摘要，并推进事实缓存版本。即使还没有当前事实，也要留下屏障，防止之后从旧原文恢复。

“忘记我之前的型号”“删除我之前的设备型号记录”“忘记回答风格”均能确定目标。自由笔记和预算记录需要在本人现有/未来计划中唯一定位；“忘记我的预算”对应多条预算时先澄清，不能全部删除。按ID删除API使用同一个底层事务函数；按ID只删除对应对象，明确不带对象的自然语言属性删除可以覆盖该属性的所有对象。

`initialize()`会幂等为旧版deleted事实补齐读取屏障，防止升级后只保护新发生的删除。

**为什么要来源水位：** 删除前的旧事实停止使用；之后用户主动重新提供的新事实可以生效。新来源不会自动解禁以前的原文。

## 4. 所有上下文入口执行相同策略

集中规则位于 `memory/access_policy.py`。

| 路径 | 具体处理 |
|---|---|
| 近期消息 | 按整轮检查，避免只删用户事实却留下助手转述 |
| 摘要 | 删除事务作废本人所有会话旧摘要；之后只从安全原文重建，原文不删 |
| 结构化事实/缓存 | 校验SQL当前状态、版本、对象及来源水位 |
| 历史检索 | 排序和新Embedding之前过滤，SQL恢复原文后再过滤；过去日期不会绕过 |
| 向量索引 | 被排除的历史候选不新建向量，尝试清理对应旧向量；SQL仍作最后裁决 |
| 历史搜索API | 与聊天共用历史检索器和遗忘策略 |
| 原始档案浏览 | 本人授权后仍能看原文，用于审计；不等同于允许输入模型 |
| 检查点恢复 | 遗忘版本变化后拒绝恢复旧执行，要求重新发送请求 |
| 正在生成的回答 | 每次向外发送事件及最终归档前复核版本，变化即停止沿用旧输入 |

日期/会话范围解析独立为 `memory/history_retrieval.py` 的 `parse_history_scope()`；是否检索由读取计划决定。非法日历日期明确报错或澄清，不默默放宽到全部历史。

普通更正仍允许查看当时事实；明确遗忘禁止恢复相应旧来源。原来的 `sanitize_reference()`继续处理更正旧值，不能代替新的遗忘策略。

**边界：** 这是停止使用个人记忆，原始会话档案仍按保留策略保存。第一版采用有来源的字面属性/值与整轮保守过滤，不声称任意自然语言转述均可精准擦除；自由笔记删除可能保守排除更多旧片段。已发送的流式内容无法撤回。恢复旧检查点采用拒绝策略，没有实现自动重建后续全部图状态。

## 5. 多设备不再只靠提示词

`services/chat_service.py`检查召回结果的 `needs_clarification`。多台设备而未指定对象，或同对象存在未解决冲突时，服务直接询问具体设备。改前只是把澄清提示塞给模型，模型仍可能自行选一台回答。

明确遗忘成功也由服务给出准确确认：“已停止使用指定的个人记忆；原始会话档案仍按保留策略保存。”目标不明确时不会确认成功。

用户明确陈述若已事务提交，后续助手生成失败不会撤销这条陈述。失败的助手回答/结论不作为普通历史证据；没有提交成功的数据不能召回。

## 6. Embedding切换与重建

`model/factory.py`原先写死v4，现在读取 `config/rag.yml` 的 `embedding_model_name`，允许 `EMBEDDING_MODEL_NAME`作显式覆盖。本次固定为 `text-embedding-v3`、1024维，每批最多10条，不做自动跨模型回退。

`model/embedding_space.py`按模型名、维度、接口生成不含密钥的指纹。个人事实、历史、产品知识库分别使用对应向量空间的独立集合；产品入库去重清单也独立，避免“新集合是空的，但旧清单告诉它已经入过库”。旧v4集合保留，不混查。

真实接口验证两条文本均返回1024维。产品知识库已重建326个分片，提供方报告Embedding输入36543 Token；参考原价单列，实际扣款未知。个人事实和历史索引在实际需要检索时按SQL有效来源增量建立。

模型/维度说明及参考价格来自阿里云官方同步Embedding文档：
https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api

这轮问答验收固定使用qwen3-omni-flash；默认应用聊天模型的可用额度仍需在部署环境满足。没有把不同回答模型的结果拼成一轮。

## 7. 验证与对照范围

功能回归使用真实SQLite和Redis；MySQL未配置测试库时跳过，不声称验证了MySQL。主要覆盖自然语言遗忘变体、短期窗口、跨会话摘要、日期回查、预算歧义、未来计划取消、重新提供事实、相同型号不同对象、旧版软删除迁移、缓存热命中后的删除、输出中途撤回、恢复检查点和分析期间并发遗忘。

真实对照入口为 `scripts/evaluate_memory_routing.py`。旧版运行改前快照，其62个原冻结保护文件与旧验收记录全部匹配；旧、新实现都用相同的v3重新建自己的冷索引。新40题来自 `evals/memory_routing_holdout.json`，四组为近期窗口、旧记忆、新记忆、完整历史参考。源码、题目、模型和参数在首次调用前冻结。

历史准备运行各自生产分析与SQL事务；提问运行真实ChatService上下文准备，普通问答使用共同的结构化评测提示。没有把它描述为完整JWT/业务工具Agent全链路测试。新增分析、摘要、Embedding和回答费用都保留实际usage，实际支付金额为空。

实测成绩另见[记忆路由与遗忘验收报告](记忆路由与遗忘验收报告.md)，以首轮完整结果为准，不覆盖旧80题82.50%的原首测。
