# 记忆质量补充评测（2026-11-24）

本轮补充检索Precision、拒答判断、候选抽取质量、摘要关键事实保留与人工评审工具。生产提取器、摘要器、检索器和模型配置未因本轮结果修改。测试集是内部合成数据，存在模板相似性，未经人工二次审核；不能当作线上或外部盲测质量。

## 为什么增加这些指标

之前有Recall@3、MRR、最终短答案规则评分与Token，但还不能回答：返回了多少无关内容；是否应该拒答；写入的事实字段/对象/时间是否正确；压缩是否遗漏关键事实。人工评分字段为空，也缺少实际填写入口。

现在分别增加确定性评分和原始输出保存。历史检索/回答复用上次冻结的48题、192条真实回答，不重新调用模型也不改原始记录；抽取新编12例校准＋48例验收，摘要新编6例校准＋24例验收，调用真实qwen3.5-omni-flash和现有生产模块。金标准不传给被测模型。

## 检索Precision与无答案判断

在42道有必要证据的问题上计算：固定Precision@3＝命中的必要证据数÷3；实际返回精确率＝命中的必要证据数÷实际返回数，逐题宏平均与所有返回微平均分开。以冻结的gold轮次为必要证据标签，尚未人工标注所有片段的广义主题相关性。

| 方法 | 固定Precision@3 | 实际返回精确率宏平均 | 实际返回必要证据比例（微平均） | 无证据题返回非空 |
|---|---:|---:|---:|---:|
| BM25 | 37.30% | 51.59% | 47/105＝44.76% | 1/6 |
| 语义 | 38.10% | 49.21% | 48/112＝42.86% | 6/6 |
| 混合 | 38.10% | 49.21% | 48/112＝42.86% | 6/6 |

固定Precision@3的标签理论上限在此集是38.10%：多数题只有1条必要证据，仅6题需2条，42题合计48条，48÷(42×3)＝38.10%。因此不能看到38.10%就说只找对了38%的问题，问题命中仍是42/42；同时，实际返回112条只有48条是标注必要证据，也确实说明上下文中有额外候选。后续应在开发集评估证据充足性、动态K或阈值，而不是继续只追求正例Recall。

拒答评测以abstain严格布尔标记做混淆矩阵，文字内容、禁止值泄露另计。7个应拒答问题包括6个无可用证据题和1个遗忘题；41题有答案。接口错误/缺失不计为正确拒答。

| 方案 | 拒答Precision | 拒答Recall | 拒答F1 | 有答案却拒答 | 6个无证据题正确拒答 | 遗忘题标记 |
|---|---:|---:|---:|---:|---:|---|
| 仅近期 | 17.07% | 100% | 29.17% | 34/41 | 6/6 | 正确 |
| 摘要＋近期 | 20.59% | 100% | 34.15% | 27/41 | 6/6 | 正确 |
| 当前记忆 | 100% | 85.71% | 92.31% | 0/41 | 6/6 | 错误 |
| 完整历史 | 100% | 85.71% | 92.31% | 0/41 | 6/6 | 错误且重述旧值 |

仅近期方案拒答很多，是因为当前题集需要的跨会话/早期信息不在它的上下文中；这不能简单解释为模型拒答策略差。当前记忆的遗忘题自然语言正确说明已遗忘，但abstain=false，不等于其文本泄露旧型号。6/6无证据题正确拒答也不证明生产已建立专门的充分证据判定器，本轮只测量现有上下文＋相同提示词下的行为，没有增加生产阈值。

## 候选事实抽取质量

调用现有FactExtractor.extract，比较纯规则与规则优先/模型补充。48题含31个有候选的正例、17个不该写入的负例，合计33个金标准候选。指标严格要求字段、值、对象、动作、生效时间同时正确；笔记值只匹配预先标注的有限别名。重复预测按额外FP计，一对一最大匹配避免重复加分。

| 模式 | TP | FP | FN | Precision | Recall | F1 | 案例完全正确 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 规则 | 23 | 4 | 10 | 85.19% | 69.70% | 76.67% | 38/48 |
| 规则＋真实模型补充 | 29 | 4 | 4 | 87.88% | 87.88% | 87.88% | 44/48 |

17个负例均未产生候选，未发现无原文字面依据的候选值；这不代表所有语义误记或攻击都已覆盖。规则＋模型模式有16题真正调用模型，其余由规则或入口过滤直接完成，不能说48题全靠模型抽取。

四个严格匹配错误均是有效时间遗漏。例如原文“从2026-12-10起，我家是木地板”，正确候选应含valid_at=2026-12-10；规则返回木地板却留valid_at为空。因为规则已经返回候选，模型补充不会再次处理它。一个不完整候选按严格匹配计1个FP和1个FN，不能解释为多编造了4条无依据事实。这是候选层质量结果；未来生效事实的数据库保存/召回行为还需独立验证。

## 摘要关键事实保留

调用生产BatchSummarizer，预算沿用summary_input_budget=16000、summary_budget=1024、max_batches=8和原有超时。模型只收到旧摘要和双方原文。24题标注128个关键事实，覆盖型号/编号、否定与未解决状态、更正、日期时间、预算约束和分批摘要。

- 规则匹配保留125/128＝97.66%；21/24个摘要保留全部标注关键事实。
- 4个长案例均实际分为4批，不是用写死摘要测试多批路径。
- 未检测到预定义的错误修复声明或无来源英文数字编号；这些检查不能覆盖所有语义幻觉，不能称“摘要幻觉率0%”。
- 成功摘要输出与旧摘要＋原文的UTF-8字节总量比约5.13%。此数由长样本权重主导，不是Token压缩率或成本降低比例。

3项未匹配中，test-correction-00和03确实遗漏维修编号TK-10020/TK-10023。test-negation-00写“问题依旧”，语义上保留未解决状态，但冻结别名未包含这个说法，是规则假阴性。辅助代码审阅记录在quality-assisted-review-20261124.json，方法明确是assistant_semantic_inspection，不算人工评分。不根据验收结果回改冻结别名，也不把97.66%直接称为完整语义真值。

本轮真实验收共53次模型调用：36次摘要调用、17次提取调用（16题，其中含一次格式/证据校验重试）；全部成功且取得usage。输入79055、输出5341 Token。另有校准调用，单独保留，不与验收混合；重评分没有新增模型请求。

## 人工复核怎样做

入口：evals/runs/quality-human-review-20261124/review.html。页面隐藏方案名和规则分数，逐题显示一个模型回答；左边是截至提问时本人全部可用原文，按时间排序，不是检索排名。默认只显示金标准证据，可取消勾选检查全部原文及后续更正/遗忘要求。不能仅因为某条排在最上面就认定它最新或最相关。

每次评右侧回答，不是逐条给左边历史评分：

1. 先看当前问题需要哪些信息，定位能支持答案的原文。
2. 检查后面是否有更正、日期限制、遗忘要求；普通无关外观记录可跳过。
3. 分别判断自然语言内容是否正确完整、abstain标记是否正确、是否没有泄露禁止值。
4. 填评审人并保存；导出JSON后由脚本校验来源/回答指纹和填写项，再汇总。

页面第一个例子：原文确认“校准定位模块，维修授权码WX-2105”，模型却答“资料不足或应当遗忘”且abstain=true。如果没有后续更正使原文失效，三项应分别选否、否、是。答案错不等于泄露，也不需要把三项全选否。有充分依据应回答时abstain应为false，无依据或应遗忘时才应为true。

页面支持浏览器本地保存、筛选未评审和JSON导出；不自动联网提交。导入以回答指纹绑定原运行，未评条目保持空白；只评部分时报告覆盖率和已评子集准确率，不外推为全量。已完成浏览器桌面/手机显示、保存刷新、导出JSON和输入校验测试，自动化交互只使用临时浏览器且未导入人工结果。

用户已要求人工复核先暂停，目前真实人工评审0/192，人工准确率为空。程序评分、辅助语义检查均不冒充人工判定。

后续用户授权当前助手完成AI复核，192条均已审阅并保存引用和理由。它分别判断任务完成与基于实际输入的合理性：当前记忆仍46/48，两个对照方案因语义假阳性分别由14/48、20/48调整为AI口径13/48、19/48；旧规则结果没有覆盖，人工评分仍空。详细发现和一条问法歧义见[记忆回答AI复核报告](记忆回答AI复核报告.md)。

## 文件、命令和边界

| 文件 | 作用 |
|---|---|
| evals/history_metrics.py、scripts/evaluate_history.py | 新增精确率和拒答混淆矩阵，未来历史评测也输出这些指标 |
| scripts/rescore_history.py | 从既有真实运行离线重算指标，不改旧基线 |
| evals/build_quality_cases.py、evals/quality_cases.json | 抽取/摘要固定标签及生成器 |
| evals/quality_metrics.py | 一对一候选匹配、事实保留、已知错误和无来源编号检查 |
| scripts/evaluate_memory_quality.py、scripts/rescore_quality.py | 真实评测及离线复核评分 |
| scripts/review_memory.py、evals/review_template.html | 方案盲评页面、来源校验及真实人工评分汇总 |
| tests/test_memory_quality_evaluation.py | 标签、分母、一对一匹配、时间、否定、计量、人评空白和复评分回归 |

```powershell
python scripts/rescore_history.py --source evals/runs/history-test-paced-20261124 --output evals/runs/NEW-history-metrics.json
python scripts/evaluate_memory_quality.py --live --suite all --split calibration --env-file .env --output evals/runs/NEW-quality-calibration
python scripts/evaluate_memory_quality.py --live --suite all --split test --env-file .env --output evals/runs/NEW-quality-test
python scripts/rescore_quality.py --source evals/runs/quality-test-20261124 --output evals/runs/NEW-quality-metrics.json
python scripts/review_memory.py export --source evals/runs/history-test-paced-20261124 --output evals/runs/NEW-human-review
python scripts/review_memory.py import --key evals/runs/quality-human-review-20261124/blind_key.json --reviews YOUR_EXPORTED_JSON --output evals/runs/NEW-human-scores.json
```

默认evaluate_memory_quality.py仅运行离线规则抽取，不调用模型；摘要套件必须显式--live。网页--refresh只允许刷新同一数据/同一回答来源，保持盲评ID、浏览器进度和状态，不覆盖已完成评审。

可提交的聚合快照在evals/baselines/quality-coverage-20261124.json；逐题原始预测、摘要、usage和指纹在evals/runs/quality-test-20261124。为修复测试发现的“跨句否定词抑制已知错误检测”评分器问题，对固定原始输出离线重新计算；所有案例分数均未变化，新评分器指纹和changed_score_cases=[]保留在quality-test-final-20261124.json。旧运行和旧基线未覆盖。
